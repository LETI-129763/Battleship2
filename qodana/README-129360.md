## Overview

This quality gate uses Qodana and GitHub Actions to detect the **Long Parameter List** code smell. Methods with excessive parameters may reduce code readability and maintainability.

## Inspection Mapping

| Code Smell (Fowler) | IDE Inspection | Inspection ID | Metric / Threshold | Limitations |
|---|---|---|---|---|
| Long Parameter List | Method with too many parameters | `ParametersPerMethod` | **PAR** (number of parameters). Default: 5; configured: 7 | Uses an absolute threshold rather than a system-relative threshold. Cannot evaluate parameter relationships or method design quality. |

The quality gate uses the following configuration files:

- `qodana-129360.yaml`
- `.qodana/profiles/profile-129360.yaml`
- `.github/workflows/qodana-smell-129360.yaml`

The inspection reports methods exceeding **7 parameters**, and the quality gate is configured to fail when at least one problem is detected.

## Quality Gate Validation

A method named `qodanaParameterListTest` was deliberately introduced in `Game.java` with **9 parameters**, exceeding the configured limit of 7.

Qodana detected the violation and the quality gate failed. The method was subsequently corrected to **6 parameters**, without changing the inspection threshold, and the quality gate passed.

The corrected `qodanaParameterListTest` method now resides in [`QualityGateExamples129360.java`](../src/test/java/battleship/QualityGateExamples129360.java), alongside the Checkstyle example and separate from production code.

| Execution | GitHub Actions |

## Reflection

Qodana successfully detected the deliberately introduced Long Parameter List, although the presence of this code smell does not necessarily indicate a defect. False positives may occur when methods legitimately require many parameters, while false negatives may occur when poorly designed methods remain below the configured threshold. Lowering the parameter limit increases detection sensitivity but may also increase the number of false positives. Unlike detection strategies that combine multiple metrics and system-relative thresholds, this inspection relies on a single absolute threshold, so manual code review remains necessary.
