## Overview

This implementation introduces a Checkstyle quality gate to enforce Java method parameter naming conventions in the Battleship2 project.

The `ParameterName` check validates parameter names against the following lowerCamelCase naming pattern:

```text
^[a-z][a-zA-Z0-9]*$
```

Valid examples include `validValue`, `playerName` and `totalShots`, while names such as `InvalidValue`, `player_name` and `TOTAL_SHOTS` violate the configured rule.

The quality gate runs automatically through GitHub Actions on pull requests targeting `master` and pushes to `master`. Naming violations are reported as errors and cause the workflow to fail.

## Limitations

Checkstyle verifies whether parameter names follow the configured naming pattern, but cannot determine whether a name is meaningful or accurately describes its purpose. For example, a generic parameter name such as `x` may satisfy the rule even when a more descriptive name would improve readability.

Additionally, the `ParameterName` check does not validate local variable names, method names or parameter names in lambda expressions. Therefore, this quality gate improves naming consistency but does not replace manual code review.
